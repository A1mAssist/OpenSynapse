# RazerLite Windows 设计规格

> Superseded by `docs/superpowers/specs/2026-08-11-opensynapse-functional-parity-design.md`. Retained as historical context only.

状态：设计草案
日期：2026-08-11

## 1. 目标

RazerLite（项目名暂定）是一个只面向 Windows 11 的轻量雷蛇设备控制器，用于替代当前机器上雷云的常用功能。它只覆盖已确认的硬件，不追求兼容所有雷蛇设备，也不复制雷云的账号、云服务和内容业务。

当前目标硬件：

- Razer Blade 16 2025，机型 RZ09-0528，USB PID `1532:02C6`
- Razer Viper V3 HyperSpeed，USB PID `1532:00B8`

已明确暂不支持：Razer USB-C Dock `1532:0F4E`、宏、固件升级和其他未列出的雷蛇设备。

## 2. 第一版范围

### Blade 16

- 性能模式：平衡、游戏、创作者和经过验证的自定义模式
- 风扇：自动模式；手动转速仅在协议、安全边界和退出行为验证通过后开放
- 键盘灯光：亮度、静态、呼吸、波浪、光谱、响应等设备实际支持的效果
- 电池：充电上限，以及插电/电池分别保存的配置（是否可写必须先通过实机验证）
- 性能显示：CPU、GPU、风扇、内存和存储分组；展示可获得的温度、功耗、占用率、频率、电压、RPM、使用率和读写速度

### Viper V3 HyperSpeed

- DPI 档位和当前档位
- 轮询率
- 基础按键映射
- 电量和休眠时间

### 通用功能

- 全局配置
- 按应用自动切换配置
- 插电/电池配置
- 托盘常驻和可选用户级开机启动
- 本地状态、错误和日志显示

### 非目标

- 账号登录、云同步、商城、新闻、游戏库、社区和遥测
- 宏录制与回放
- 固件下载和升级
- 以系统服务或常驻高权限进程替代雷云
- 在未知 PID 或未验证的协议上猜测并发送写入报文

## 3. 已知事实与风险

OpenRazer 当前设备表和 Blade 16 2025 的配置文件已经包含 `1532:02C6`，并列出设备信息、Logo、矩阵亮度和多种灯光效果；Viper V3 HyperSpeed 的配置文件列出 DPI、DPI 档位、轮询率、电量和休眠时间。这些内容可作为协议移植的起点。

旧版 `razer-laptop-control` 设备表没有 `02C6`，但后续 `blauzim/razer-ctl` 已精确列出 `RZ09-05286`、`RZ09-05288`、`RZ09-05289` 与 PID `02C6`，并实现性能模式、双风扇区状态和电池充电上限的读写；`encomjp/razer-control-revived` 也独立列出 `02C6`。这些来源把相关功能从“猜测”提升为“有型号匹配的协议证据”，但本项目仍要求每个写入在当前机器上先 GET、写入后立即 GET，并保留失败时的禁用路径。

Windows 设备枚举中已经存在 Blade 的 `RZCONTROL` 接口，这说明用户态 HID 方案值得先验证，但不证明普通用户可以直接读写所有功能，也不证明所有报文与 Linux 实现相同。

验收原则：

- “能显示”必须来自真实读数；读不到显示 `--`，不显示伪造的 `0V` 或旧值。
- “能控制”必须经过写入、读回确认、重启和异常断开测试。
- 风扇、功耗和电池功能在验证前显示为未支持，不进入可点击的控制路径。

## 4. 技术架构

### 4.1 进程模型

第一版是一个普通用户进程 `RazerLite.exe`：

- WinUI 3 / Windows App SDK 设置窗口；托盘功能使用 Win32 通知区域 API
- 用户级可选开机启动
- 默认不安装 Windows 服务
- 默认不以管理员权限运行
- 只有某项硬件操作明确要求提权时才单独请求

### 4.2 组件边界

1. **UI 层**
   - 托盘菜单、设置窗口、性能条、状态和错误提示
   - 不直接调用 HID API

2. **设备发现层**
   - 枚举 Windows HID 设备
   - 只识别 `02C6` 和 `00B8`
   - 处理热插拔、设备忙和设备断开

3. **HID 传输层**
   - 打开设备、读写报告、超时、有限重试和串行化访问
   - 不包含任何设备型号或报文字段

4. **协议层**
   - `Blade2025Protocol`
   - `ViperV3HyperSpeedProtocol`
   - 报文构造、解析、范围校验和响应校验
   - 每一项能力有明确的 `Supported`、`Unsupported` 或 `Blocked` 状态

5. **传感器层**
   - Windows 性能计数器：CPU 负载、频率、内存和存储吞吐
   - NVIDIA 能力接口：GPU 负载、温度、功耗和频率（以实际可用字段为准）
   - CPU 温度、功耗、电压和风扇 RPM：优先使用已验证的硬件接口；必要时通过隔离的传感器适配器读取
   - 单个传感器源失败不影响其他指标

6. **配置与策略层**
   - `%LocalAppData%\RazerLite\profiles.json`
   - 全局、按应用、插电和电池配置
   - 配置切换只应用变化项，并进行去抖和限频

7. **日志层**
   - 只记录本地诊断信息、设备标识、报文结果和错误码
   - 不上传、不登录、不做遥测

## 5. 数据流

启动流程：

1. 枚举设备并识别 PID。
2. 对每个设备执行只读能力探测。
3. 创建统一的设备状态快照。
4. 启动性能采样和 UI 刷新。

性能刷新流程：

1. 传感器适配器按约 `500 ms` 采样。
2. 采样结果进行单位转换、范围检查和时间戳标记。
3. UI 读取不可变状态快照，不直接访问硬件。
4. 读不到的字段标为不可用，显示 `--`。

控制流程：

1. 用户提交设置。
2. 协议层校验范围和设备能力。
3. 传输层发送一条写入报文。
4. 读取并确认结果。
5. 确认成功后更新状态并保存配置；失败则不保存。

配置切换流程：

1. 监听前台应用和电源状态变化。
2. 对匹配的配置去抖。
3. 只应用与当前状态不同的字段。
4. 某项失败时保留其他成功项，并在托盘显示警告。

## 6. 界面设计

保留截图中紧凑的横向性能条，但不复制雷云的业务页面。

### 性能页

- CPU、GPU、风扇、内存、存储分组
- 每组显示型号或名称、主要数值和小型进度条
- 不可用字段显示 `--`
- 性能模式和经过验证的风扇控制位于同一页

### 灯光页

- 亮度
- 设备实际支持的效果
- 颜色和速度等效果参数

### 鼠标页

- DPI 档位
- 轮询率
- 基础按键映射
- 电量和休眠时间

### 配置页

- 全局配置
- 按应用绑定
- 插电/电池配置
- 开机启动

不加入显示、声音、账号、商城和游戏内容页面。

## 7. 容错与安全

- 设备被雷云占用时进入只读模式，不自动结束雷云进程。
- 设备断开时停止写入，保留配置并等待重连。
- HID 超时采用有限重试；连续失败后把该能力标为不可用。
- 所有数值在协议层做边界校验。
- 所有写入做读回确认。
- 异常温度、RPM、电压和功耗值丢弃，不显示为有效数据。
- 手动风扇模式只有在确认硬件安全边界和退出行为后开放；在此之前不提供写入入口。
- 不因为 UI 崩溃而引入后台服务或高权限守护进程。

## 8. 分阶段验收

### M1：硬件探测

- 正确识别 `02C6` 和 `00B8`
- 正确处理断开、重连和设备忙
- 只读探测不会改变设备状态

### M2：只读性能与基础控制

- 性能条稳定刷新
- CPU/GPU/内存/存储显示真实数据
- 键盘灯光读写通过读回确认
- 鼠标 DPI、DPI 档位、轮询率读写通过读回确认

### M3：笔记本专属功能

- 风扇读数和控制
- 性能模式
- 电池充电上限
- 每项分别通过重启、断电、插电、设备重连和错误恢复测试

### M4：日常替代

- 托盘常驻和用户级开机启动
- 按应用配置切换
- 无网络、无账号运行
- 卸载雷云后，所有已声明支持的功能仍然可用

## 9. 测试策略

- 协议单元测试：报文构造、解析、校验和边界值
- HID 回放测试：用录制的响应测试正常、错误和超时路径
- 传感器测试：缺失字段、异常值、短暂断开和恢复
- 真机测试：Blade 16、Viper、重启、睡眠/唤醒、插拔、雷云占用和卸载后的行为
- 功耗/风扇测试：任何手动控制开放前，记录温度、RPM、功耗和恢复行为

## 10. 源码与许可证

OpenRazer、`mbuesch/razer` 和 laptop-control 均包含 GPL 代码。项目需要维护来源记录，区分：

- 直接移植的 GPL 代码和报文定义
- 从设备行为中观察到的协议事实
- 独立编写的 Windows HID、UI、配置和传感器代码

在实现前确认最终许可证、源码归属和第三方传感器库的许可证兼容性。第一版不引入无法明确分发条件的闭源 SDK。

## 11. 实现前置门槛

第一步必须是只读可行性探针，而不是直接做完整 UI：

1. 枚举 `02C6` 的 HID 和 `RZCONTROL` 路径。
2. 记录设备报告描述符和只读响应。
3. 验证普通用户是否可以打开接口。
4. 对已有灯光和鼠标报文做最小读写验证。
5. 单独评估风扇、功耗和电池接口。

探针未证明的能力不得进入可写 UI。该门槛用于避免用猜测报文损坏硬件或造成热管理风险。
