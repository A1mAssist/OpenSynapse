# 设备类型图标设计

日期：2026-08-13

## 目标

让 Blade 笔记本和 Viper 鼠标在概览设备列表、设备页摘要列表及设备切换入口中一眼可辨。复用 Windows 自带 Fluent 设备字形，不增加图片资产、SVG、图标包或第三方依赖。

## 图标来源与映射

- 使用系统 `Segoe Fluent Icons` 字体中的笔记本和鼠标字形。
- 图标类型只按现有 `DeviceDescriptor.ProtocolFamily` 映射：`blade-710` 为笔记本，`viper-184` 为鼠标。
- 未识别协议族使用现有通用设备字形，不通过设备名称、VID/PID 文本或显示顺序猜测。
- `DeviceRowViewModel` 暴露只读图标字形，XAML 只负责显示，不解析协议族。

## 出现位置

- 概览“已连接设备”列表：每个设备左侧保留 42px 图标块，显示对应设备类型图标。
- 设备页顶部摘要列表：增加同规格图标块，设备名称与 VID/PID 向右排列，状态保持右对齐。
- Blade/Viper 切换按钮：在设备名称前增加约 20px 的对应图标；按钮仍使用现有选择逻辑和样式。
- Blade 与 Viper 详情标题前不重复放图标，避免同一区域视觉重复。

## 视觉规则

- 摘要卡图标块使用现有 `SurfaceRaisedBrush`，圆角保持 4px。
- 图标默认使用 `AccentBrush`；切换按钮选中态继续通过现有背景色表达，不增加动画或发光效果。
- 图标至少 18px，摘要卡使用 20px，保证深色模式下清晰可辨。
- 每个图标设置明确的 `AutomationProperties.Name`：`笔记本设备` 或 `鼠标设备`。

## 范围边界

- 不修改设备发现、协议能力、读写控制或 Profile。
- 不增加设备图片、厂商 Logo、图标下载、动画或新的设备分类系统。
- 不改变设备切换按钮的点击行为和可见性逻辑。

## 验证

- x64 App 构建要求 0 warning、0 error。
- 运行全部非硬件测试，不设置 `OPENSYNAPSE_HARDWARE_TEST`。
- 启动应用检查概览设备列表、设备摘要列表和切换按钮均能区分笔记本与鼠标。
- 检查深色模式下图标轮廓清晰、标签不截断、状态文本不被挤压。
- 不点击任何硬件写入按钮。
