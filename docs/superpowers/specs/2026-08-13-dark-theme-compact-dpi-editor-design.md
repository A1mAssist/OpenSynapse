# 固定深色主题与紧凑 DPI 档位编辑器设计

日期：2026-08-13

## 目标

修正 Viper DPI 档位区域中过高输入框和松散表格造成的视觉问题，并将应用统一为固定深色主题。只调整现有 WinUI 3 资源、XAML 布局和主题初始化，不改变设备协议、提交、校验、回滚或 Profile 行为。

## 固定深色主题

- `Application.RequestedTheme` 固定为 `Dark`。
- 删除侧栏底部完整的“外观”区域，包括浅色、深色按钮和包裹卡片。
- 删除仅服务于主题切换的按钮样式、点击事件和选中状态代码。
- 主窗口初始化时直接应用深色资源和深色标题栏颜色，不保留可切换入口。
- 将现有应用语义色调整为深色底下可读的固定颜色；继续复用同一组资源键，避免修改各页面绑定。

## DPI 档位布局

- DPI 档位仍保持一个外层设置卡，不增加内层卡片。
- 标题和当前完整档位摘要单独占一行，避免与操作控件相互挤压。
- `档位数`、`活动档`和“应用档位”组成固定高度的紧凑工具栏；两个 `NumberBox` 明确使用稳定宽度、高度和底部对齐，不允许随所在网格纵向拉伸。
- 五档编辑区保持 `档位 / X / Y` 三列，使用窄编号列和两个等宽 DPI 列；每行高度一致，行间仅使用小间距。
- X/Y 继续使用原生紧凑 `NumberBox`，保留 100–30000、步进 50、禁用状态和现有双向绑定。
- 底部说明继续显示“整表提交、范围、步进、当前会话”，但不使用额外说明卡片。

## 行为边界

- 不修改 `MainViewModel` 的 DPI 档位集合、数量变化、活动档收敛、归一化、提交和失败回滚逻辑。
- 不修改任何硬件 setter，也不在视觉验收中点击应用按钮。
- 不增加主题配置持久化，因为应用只保留深色模式。

## 验证

- x64 App 构建要求 0 warning、0 error。
- 运行全部非硬件测试，不设置 `OPENSYNAPSE_HARDWARE_TEST`。
- 启动应用确认侧栏底部无“外观”区域，所有页面均为深色。
- 检查 Viper DPI 档位区域：顶部工具栏无大块空白，五档完整可见且无重叠、截断或嵌套卡片。
- 未经额外授权，不执行任何硬件写入。
