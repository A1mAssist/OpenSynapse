# OpenSynapse 功能对齐设计规格

- 状态：已批准范围，待规格复核
- 日期：2026-08-11
- 平台：Windows 11 x64
- 前端：WinUI 3 / Windows App SDK
- 目标设备：Razer Blade 16 2025 (`1532:02C6`) 与 Razer Viper V3 HyperSpeed (`1532:00B8`)

本文档取代 `2026-08-11-razer-lite-design.md` 作为后续功能开发的设计依据。旧文档和已有实施计划保留为历史记录，不代表当前范围。

## 1. 根本目标

OpenSynapse 要解决的问题不是复刻 Razer Synapse 的界面，而是在不依赖账号、云端和内容业务的前提下，让当前两台设备的日常控制能力可以由一个轻量、可验证的 Windows 应用完成。

功能完成的判定不是“界面上存在控件”，而是：

1. 能力确实适用于目标设备。
2. 后端有官方资料、公开源码、雷云通信记录或真机响应作为依据。
3. 写入结果可以通过读回、设备响应或可重复的真机行为验证。
4. 前端只在能力可用时开放操作，并准确展示失败原因。
5. 重启、睡眠、设备断开、雷云占用和异常退出不会留下危险状态。

## 2. 当前范围

### 2.1 Razer Blade 16 2025

#### 自定义

- 本地设备配置选择与管理。
- Standard 与 Hypershift 两套按键分配。
- 非宏按键分配：默认、键盘功能、鼠标功能、灵敏度功能、多媒体、Windows 快捷方式、启动程序、切换配置和禁用。
- 支持相关按键的 Turbo/重复行为，但不扩展为宏编辑器。
- Gaming Mode：Windows 键、Copilot 键、Alt+Tab、Alt+F4 的禁用策略。
- Snap Tap。
- F1-F12 标准功能与多媒体主功能切换。
- 触控板和高级指针选项使用 Windows 原生设置入口，不复制 Windows 设置页。

#### 性能

- 雷云对该型号实际提供的性能模式。
- CPU Voltage Optimizer。
- 风扇 Auto、Fixed RPM 和 Manual Fan Curve。
- 手动曲线分别响应 CPU/GPU 温度；具体节点、范围和风扇通道以雷云实际配置与协议验证结果为准。
- CPU、GPU、风扇、内存和存储的真实状态展示；读不到的字段显示 `--`。

#### 显示

- 当前分辨率和刷新率展示。
- 支持的刷新率切换。
- 电池供电时自动切换刷新率。
- NVIDIA Optimus 状态由 Windows/Razer 平台路径管理；本机为 Optimus-only，Dedicated GPU-only/GPU MUX 明确不在 OpenSynapse 范围内。
- 外接显示器和其他显示选项使用 Windows 原生设置入口。

#### 电池

- Battery Health Optimizer 开关。
- `50%` 到 `80%` 的充电上限，以设备实际允许的步进为准。
- 单次充满。
- 当前电源来源、电量和充电策略状态。

#### 系统灯光

- 灯光总开关。
- 插电和电池状态分别设置亮度。
- 两种电源状态的亮度联动/解除联动。
- Logo 灯光模式。
- 显示器关闭时熄灯。
- 空闲指定时间后熄灯。
- 插电/电池熄灯策略联动/解除联动。
- 低于指定电量时熄灯。

#### 快速灯效

- Ambient Awareness：选择或自定义屏幕取色区域。
- Audio Meter：Color Boost。
- Breathing：单色、双色、随机色。
- Fire。
- Reactive：颜色和持续时间。
- Ripple：颜色。
- Spectrum Cycling。
- Starlight：单色、双色、随机色和持续时间。
- Static：颜色。
- Wave：从左到右、从右到左。
- Wheel：顺时针、逆时针。
- 灯效参数保存到本地配置，并支持按应用和电源状态切换。

### 2.2 Razer Viper V3 HyperSpeed

#### 自定义

- 一个板载配置。
- Standard 与 Hypershift 两套按键分配。
- 非宏按键分配：默认、键盘功能、鼠标功能、灵敏度控制、多媒体、Windows 快捷方式、启动程序、切换配置和禁用。
- 支持相关按键的 Turbo/重复行为。
- 灵敏度功能：Clutch、档位上调/下调、即时灵敏度、档位正向/反向循环。

#### 性能

- 最多五个 DPI 档位。
- 当前档位选择与显示。
- X/Y 灵敏度联动或独立设置。
- 当前 X/Y DPI 范围 `100` 到 `30000`，步进为 `50`；DPI 档位仍需独立硬件验证。
- `125`、`500`、`1000 Hz` 轮询率。
- 只有检测到兼容 HyperPolling 接收器并验证协议后，才显示 `2000`、`4000` 或 `8000 Hz`。
- Windows 鼠标属性入口。

#### 电源

- 电量百分比。
- 空闲休眠时间。
- 低电量节能策略。
- Alkaline、Lithium、Rechargeable NiMH 电池类型。

### 2.3 通用能力

- 本地配置的创建、重命名、复制、删除、导入和导出。
- 配置与应用可执行文件绑定，前台应用变化时自动切换。
- 插电和电池供电状态使用不同配置。
- 托盘常驻。
- 可选的用户级开机启动。
- 本地诊断状态与日志，不上传遥测。

## 3. 明确延期和排除

以下能力不进入当前实现计划，也不创建占位接口、空页面或禁用按钮：

- 高级灯效编辑器、逐键绘制、区域效果组合、Chroma Studio 图层和时间轴。
- 宏录制、宏编辑、宏回放和宏按键绑定。
- Viper Smart Tracking、抬起距离、非对称截止和落地距离校准。
- 与范围外 Chroma 设备进行跨设备同步；当前 Viper 没有可同步的 Chroma 灯光，因此本期没有 Chroma Sync 目标设备。

以下内容不属于 OpenSynapse：

- Razer 账号、云同步、商城、新闻、游戏内容、社区和遥测。
- 固件下载与升级。
- 未列出的 Razer 设备。
- 对未知 PID 或未知命令进行模糊测试和猜测写入。
- 为未来可能需要的设备提前建立插件系统、通用设备框架或协议 DSL。

## 4. 证据等级与当前能力矩阵

能力状态只有以下四种：

- `Verified`：已在当前真机完成读取、写入和读回/恢复验证。
- `SourceBacked`：有官方手册或公开协议源码依据，但尚未在当前真机完成全部验证。
- `Native`：由受支持的 Windows API 或系统设置提供，不需要 Razer 私有命令。
- `Blocked`：雷云有该功能，但当前没有足够协议证据；禁止提供可写入口。

| 能力 | 当前证据 | 状态 | 验证方式 |
|---|---|---|---|
| Blade 键盘亮度 | `FF / 0E / 84` 读取，`FF / 0E / 04` 写入 | `Verified` | 写入后读取并比较原始亮度值 |
| Blade 固件灯效：关闭、波浪、光谱、响应、静态、呼吸、星光 | OpenRazer Blade 16 2025 支持记录和命令构造 | `SourceBacked` | 命令成功、真机目视、恢复原效果 |
| Blade 自定义矩阵 | `6 x 17`，效果类 `03`、矩阵命令 `0B` | `SourceBacked` | 固定测试帧、CRC/参数测试、真机逐区检查 |
| Ambient Awareness、Audio Meter、Fire、Ripple、Wheel | 官方功能表；需要矩阵软件渲染 | `SourceBacked` | 确定性渲染测试和持续真机运行 |
| Blade 插电/电池亮度、Logo、熄灯策略 | 官方功能表，除现有亮度外命令未验证 | `Blocked` | 雷云通信对照、读取、写入、读回和恢复 |
| Blade 按键、Gaming Mode、Snap Tap、Fn 主功能 | 官方功能表，命令未验证 | `Blocked` | 雷云通信对照和行为测试 |
| Blade 性能模式、CPU Voltage Optimizer | 官方功能表，EC/HID 命令未验证 | `Blocked` | 读取当前值、单项复现、读回、重启恢复 |
| Blade Auto/Fixed/Manual 风扇 | 官方确认 2025 型号支持手动曲线，命令未验证 | `Blocked` | 温度/RPM 记录、边界和异常退出恢复测试 |
| Blade 刷新率和 Windows 显示入口 | Windows 显示 API/设置 | `Native` | 应用后查询当前显示配置 |
| Blade 电池充电上限/单次充满 | 官方确认 `50%` 到 `80%`，命令未验证 | `Blocked` | 读回、重启、关机充电和 USB-C PD 测试 |
| Viper 电量 | 已有真机读取 | `Verified` | 连续读取与雷云显示交叉检查 |
| Viper 当前 X/Y DPI | 已有读取、写入、读回和恢复 | `Verified` | 写入后读取 X/Y 并比较 |
| Viper 轮询率 125/500/1000 Hz | 已有读取、写入、读回和恢复 | `Verified` | 写入后读取原始轮询率代码 |
| Viper 休眠时间 | 已有读取、写入、读回和恢复 | `Verified` | 写入后读取秒数并比较 |
| Viper DPI 档位和当前档位 | 官方功能表，当前命令未验证 | `Blocked` | 雷云通信对照、板载保持和重新插拔测试 |
| Viper 按键、Hypershift、板载配置 | 官方功能表，当前命令未验证 | `Blocked` | 雷云通信对照、重新插拔和无雷云测试 |
| Viper 低电量策略和电池类型 | 官方功能表，当前命令未验证 | `Blocked` | 读取、写入、读回和电量估算对照 |
| 本地配置、应用绑定和电源状态切换 | Windows 事件和本地 JSON | `Native` | 单元测试和端到端切换测试 |

`Blocked` 表示需要完成协议研究，并不表示从产品范围删除。协议没有验证前，普通页面不显示虚假的可操作控件；诊断页可以显示能力名称、阻塞原因和证据状态。

## 5. 实现策略

采用协议门控的纵向功能切片。每个切片按以下顺序完成：

1. 核对官方功能和适用型号。
2. 从现有源码、驱动清单或雷云通信中取得命令证据。
3. 增加最小协议构造与解析测试。
4. 在真机上执行读取或无状态探测。
5. 执行受控写入、读回和恢复。
6. 后端能力状态改为可用。
7. 增加对应 WinUI 3 控件并完成错误状态。
8. 完成重连、睡眠和雷云占用测试。

不采用“先把所有控件画出来”的方式，也不等待所有协议都破解后才交付第一批功能。

## 6. 后端设计

### 6.1 进程模型

第一选择是单个普通用户进程 `OpenSynapse.exe`：

- WinUI 3 主窗口和托盘共享同一个应用进程。
- HID/EC 访问、灯效渲染、配置切换和状态采样都在该进程内。
- 默认不安装 Windows 服务，不常驻高权限进程。
- 只有按键映射经验证确实需要跨权限工作时，才单独设计最小辅助进程；当前不预建。

### 6.2 复用与最小拆分

保留现有可工作的 `RazerFeatureTransport`、`RazerFeatureReport`、设备发现和系统性能采样代码。当前 `RazerDeviceTelemetryReader` 在新增功能后会失去清晰边界，因此只做以下必要拆分：

- `Blade16Controller`：Blade 读取、灯光、性能、风扇、显示、电池和键盘能力。
- `ViperV3HyperSpeedController`：Viper 电量、DPI、轮询率、休眠、板载配置和按键能力。
- `OpenSynapseCoordinator`：设备热插拔、能力状态、当前配置和 UI 状态快照。
- `QuickLightingEngine`：只实现官方快速灯效所需的软件帧，不包含高级编辑器模型。
- `ProfileStore`：通过 `System.Text.Json` 读写本地配置。

不为每个功能创建单独接口，不建立一实现接口、工厂、插件加载器或数据库。

两个设备控制器复用同一个传输实现。传输层按规范化设备路径串行化请求：同一 HID collection 的报告保持严格顺序，Blade 与 Viper 的不同路径可以并行，避免连续灯效阻塞鼠标状态查询。

### 6.3 能力状态

每项设备能力独立维护状态：`Unavailable`、`Blocked`、`Ready`、`Busy`、`Failed`。一次查询失败只影响对应能力，不使整个设备页面失效。

UI 使用不可变状态快照。ViewModel 不构造 HID 报告，也不根据产品名称猜测支持能力。

### 6.4 协议安全门

- 只打开 VID/PID 和 HID collection 均匹配的接口。
- 写入前必须成功读取相同设备路径上的匹配能力，或者有雷云抓包证明该能力没有读取命令。
- 有 GET 命令时执行 `读取 -> 写入 -> 读回 -> 比较`。
- 测试性写入先选择与当前值相同的值，再进行最小变化，并恢复原值。
- 性能、风扇、电池、CPU 电压和 GPU 模式禁止枚举命令和值域。
- 设备断开、响应错序、CRC 错误、忙或超时后立即停止该能力的后续写入。
- Synapse 占用设备时不结束其进程；OpenSynapse 进入只读/忙状态并给出明确提示。

### 6.5 快速灯效

精确匹配固件能力的效果直接使用持久化硬件效果，减少后台开销。需要逐帧计算的效果通过 `6 x 17` 自定义矩阵输出：

- Ambient Awareness 使用 Windows 屏幕捕获，只采样用户选择区域的必要像素。
- Audio Meter 使用 WASAPI loopback 获取系统输出电平。
- Reactive 和 Ripple 使用 Windows 键盘输入事件。
- Fire 和 Wheel 使用确定性软件渲染器。
- 帧发送采用最新帧优先、合并积压帧和单设备串行化，禁止无限队列。
- 实际刷新率由真机稳定性测试确定，不在设计阶段猜测固定值。
- 效果停止、应用退出、设备断开或切换配置时恢复已保存的持久效果或关闭软件渲染。

### 6.6 配置

配置存储在 `%LocalAppData%\OpenSynapse\profiles.json`，使用带版本号的 JSON：

- 全局默认配置。
- Blade 与 Viper 的设备设置。
- 插电和电池状态覆盖项。
- 可执行文件路径到配置的绑定。
- 当前选择的快速灯效和参数。

保存采用临时文件加原子替换，解析失败时保留损坏文件并回退到安全默认值，不静默覆盖用户数据。

## 7. 前端设计

继续使用 WinUI 3 和 OpenSynapse 自己的界面，不复制雷云视觉样式。导航只包含当前范围：

- 概览：设备状态和系统性能。
- Blade：自定义、性能、显示、电池。
- 灯光：系统灯光和全部快速效果。
- Viper：自定义、DPI/轮询率和电源。
- 配置：本地配置、应用绑定、插电/电池策略、启动行为。
- 诊断：设备路径、能力状态和最近错误。

不提供“灯光工作室”“宏”“Viper 校准”页面。

交互规则：

- 普通且可逆的设置即时应用，并使用短防抖避免滑块连续发送报文。
- 电池策略、固定风扇和手动风扇曲线需要明确确认；GPU MUX/Dedicated GPU-only 不适用于本机且不提供控件。
- 操作进行中保持控件尺寸稳定，并禁用同一能力的重复提交。
- 写入失败时恢复控件显示值，不把失败值保存到配置。
- 不可用值显示 `--`；不显示伪造的零值、估算状态或已过期状态。
- 只在诊断页展示协议状态术语，日常页面使用清楚的用户语言。

## 8. 命名迁移

功能开发前统一把以下标识从 `RazerLite` 改成 `OpenSynapse`：

- 解决方案、项目目录、项目文件和测试项目。
- 程序集名、默认命名空间、XAML `x:Class` 和应用清单标识。
- 可执行文件、窗口标题、README 和构建命令。
- 本地数据目录和日志目录。

迁移完成后，仓库中的有效源码、项目文件和用户文档不应继续包含 `RazerLite`。历史设计和历史计划可以保留旧名称，但必须标明已被取代。

## 9. 交付切片

### S0：改名与基线

- 完成 OpenSynapse 命名迁移。
- 当前 Blade 亮度和 Viper 电量/DPI/轮询率/休眠能力继续通过测试。
- 记录当前真机状态，确保后续协议研究可恢复原设置。

### S1：协议探针与证据表

- 建立只读能力探针和原始报告记录。
- 对照雷云逐项采集当前范围内的未知命令。
- 为每项能力记录命令来源、适用 collection、参数范围、读取方法和恢复方法。
- 没有证据的写入不进入后续切片。

### S2：Blade 灯光对齐

- 完成全部系统灯光设置。
- 完成全部 11 种快速灯效和参数。
- 验证持续软件灯效不会阻塞其他设备查询。
- 验证电源变化、熄屏、空闲、低电量和应用退出行为。

### S3：Viper 对齐

- 完成 DPI 档位、当前档位和 X/Y 设置。
- 完成板载配置、非宏按键映射、Hypershift 和 Turbo。
- 完成休眠、低电量策略和电池类型。
- Viper 校准保持延期，不为它扩展此切片。

### S4：Blade 系统控制

- 完成键盘自定义、Gaming Mode、Snap Tap 和 Fn 主功能。
- 完成性能模式和 CPU Voltage Optimizer。
- 完成 Auto/Fixed/Manual 风扇。
- 完成刷新率、充电上限和单次充满；GPU MUX/Dedicated GPU-only 已明确排除。

### S5：日常替代

- 完成本地配置、导入导出、应用绑定和电源状态切换。
- 完成托盘和用户级开机启动。
- 卸载或完全退出 Synapse 后，当前范围的已验证能力仍可工作。

### S6：稳定性验收

- 重启、睡眠/唤醒、设备插拔和应用崩溃恢复。
- Synapse 占用、设备忙、访问被拒绝、超时和损坏响应。
- 长时间快速灯效、配置反复切换和多能力并发操作。
- 所有失败路径都保持真实状态且不损坏本地配置。

## 10. 测试与验收

### 自动化测试

- HID 报告构造、CRC、响应匹配、数据长度和错误状态。
- 每项已知协议的边界值和无效输入。
- 配置版本、损坏 JSON、原子保存和应用匹配。
- 快速灯效确定性帧、颜色范围、方向和持续时间。
- 能力失败隔离、取消、设备断开和状态恢复。
- ViewModel 只在 `Ready` 时允许操作，失败时恢复显示值。

### 真机验收

- 每项硬件能力保存原值、执行最小变化、读回并恢复。
- 重新插拔、注销、重启和睡眠/唤醒后复核持久状态。
- 验证雷云关闭、运行和设备占用三种情况。
- 固定/手动风扇记录温度、RPM、退出恢复和异常终止行为。
- 电池策略验证插电、USB-C PD、关机充电和单次充满。
- 软件灯效连续运行，确认无报告积压、设备失联或不可恢复闪烁。

### 完成定义

一个切片只有同时满足以下条件才完成：

- 后端能力已验证，而不是只实现了报文构造。
- 前端控件可完成真实任务，没有占位按钮。
- 自动化测试通过。
- 对应真机检查完成并留下结果记录。
- 错误、断开和恢复路径已验证。
- README 只声明实际完成的能力。

## 11. 对抗式审查与风险控制

### 风险 1：公开协议适用于相近设备，但不适用于当前 PID

控制：公开源码只把能力提升到 `SourceBacked`；必须用 `02C6` 或 `00B8` 的正确 collection 做真机验证后才能变成 `Ready`。

### 风险 2：灯效连续帧挤占 HID 通道

控制：最新帧优先、丢弃过期帧、串行访问和实测刷新率；持续灯效必须与 Viper 查询并行运行通过稳定性测试。

### 风险 3：风扇或 CPU 电压设置在异常退出后持续生效

控制：在确认固件退出行为前不开放控件；如设置会危险地持久化，再根据证据增加最小看护机制，不能先假设需要服务。

### 风险 4：软件按键映射无法作用于提权程序或受保护游戏

控制：优先寻找和使用板载/设备驱动支持；本地输入方案必须明确验证权限边界，不能把普通 `SendInput` 宣称为完整板载能力。

### 风险 5：功能范围再次膨胀，产生大量半成品页面

控制：只按 S0-S6 纵向切片交付。高级编辑器、宏和 Viper 校准没有重新批准前不进入实现计划。
