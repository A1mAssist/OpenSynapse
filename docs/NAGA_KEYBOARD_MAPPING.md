# Naga 与键盘媒体键映射

本轮修复按型号区分 Naga 的固件按键、侧板和私有输入编号，并补齐键盘媒体键的编辑入口、独立键盘服务的映射读写。

## Naga 的型号与侧板

固件 `0x40..0x4B` 是 12 键侧板，`0x50..0x55/56` 是 6/7 键侧板。它们与键盘输出 HID usage、私有报告编号属于不同编号空间。映射页现在按产品解析固件编号，并显示侧板键数；右键、中键和侧板按键不会再被私有报告表改名成 Key1、Key2、Profile 或 DPI。

设备没有返回按键清单，或拒绝 `02:84` 时，使用以下产品清单。清单包含该产品支持的侧板槽位；它不表示当前安装的侧板已经被检测到。固件拒绝读取的槽位显示不可读并禁止编辑。

图片上没有定位的侧板按键放入下方映射列表，按侧板键数和按键编号命名，避免多套侧板的条目把图片与连线区域撑得过长。

Hex V2 `0050` 的官方包声明 `isOBMDevice:false`；更早产品没有本轮确认的相同 OBM 契约，未给这些型号添加推测的固件清单。

Naga 侧键的软件宏原路径会写入 Off，但运行时的 `NagaSideButton` 事件来自普通键盘 Raw Input，尚无独立且可抑制的侧键输入桥。因此本轮禁止新增侧键软件宏、软件 Windows 快捷操作与隐式主机转发。设备支持的固件映射和板载宏继续使用原路径。旧软件绑定保留供删除和恢复，页面显示其不可用状态；保存其他按键不会把旧软件宏改成板载宏。

Raw Input 事件、宏匹配、按住状态和恢复设备选择现在携带规范化产品身份及物理实例。Naga Pro 的有线/接收器身份可以归属同一产品，但两台同型号鼠标不会共享按住状态；恢复时遇到多个候选设备会拒绝选择。

V3 Pro 的 HyperShift 固件编号 `0x39` 对应私有编号 `89`，额外按键 `0x80` 对应 `210`。软件 HyperShift 观测仍关闭，避免鼠标事件改变其他设备的全局软件层；BLE 路径同样不宣称可观测软件层。固件普通层与 HyperShift 层可分别编辑。

## 键盘右上角按键

上一曲、播放/暂停、下一曲的固件编号分别为 `201 / 205 / 202`，软件私有事件编号分别为 `84 / 85 / 83`。它们始终加入键盘映射清单，包含设备返回非空但不完整清单、以及只能使用模拟轴布局兜底的情形。

Huntsman Elite、BlackWidow Elite、BlackWidow V3 Pro、Huntsman V2 Analog、Huntsman V2 的 Chroma 图形将三个媒体键作为一个灯光选区。映射页将这个已知选区分成按物理顺序排列的三个可点击按钮；Ornata V2、BlackWidow V4/V4 Pro 使用各自独立的媒体选区。按钮有本地化名称、工具提示和自动化入口，点击直接打开对应编辑项。下方列表保留为备用入口。

定向协议验证覆盖 `0226、0228、025A、025C、025D、025E、0266、026C、0287、028D、0293、02CF` 的媒体键。Huntsman V3 Pro `02A6` 按产品自身清单处理播放/暂停及两个多功能按键 `205 / 208 / 209`，不套用旧款三媒体键清单。`0266` 写入保持模拟轴阈值，`02A6/02CF` 保持 `02:9E` 读取和 `02:0D` 写入。

独立 `RazerKeyboardService` 原先能够探测 `02:8F`，但后续读写没有相应分支。现补齐普通键表 `02:8D` 或 analogV3 的 `02:9E` 读取，以及 `02:0D` 写入。读回同时核对 profile、按键、层、功能和数据；失败时向原 profile 恢复原映射并再次验证。独立键盘页也向命名目录传入产品型号，使固件键号能正确显示。

## 证据与验证

协议依据为本地保存的官方 middleware bundles：各产品 `main.*.js` 的默认输入表、共享 fwID 表和 OBM 引擎 `getButtonIdFromUIMappingList`。Naga V3 Pro 的两条特殊编号来自 `00E7/main.5df0b811a655362f71f5.js`。键盘媒体编号可在 `02A6/6737.b4bf391c075aa0879a1d.js` 的 `DKM_KBMK_01..04` 表复查。图形定位依据官方 `DeviceManifest_<十进制 PID>_0.json` 中的 `Media_Selection`，没有按外观推测固件编号。

本地测试位于忽略的 `tests/OpenSynapse.Core.Tests/`：`KeyboardMediaMappingTests`、`NagaMappingFamilyTests` 和 `RazerHidMappingTests` 覆盖编号、型号别名、侧板范围、双层读写、拒绝清单后的兜底、读回失败恢复、软件绑定门禁、实例匹配、按住释放与 HyperShift 隔离。相关共享映射/宏输入回归通过 112 项。

WinUI 使用真实映射 ViewModel 和 View，配合模拟 transport。`artifacts/mapping-review/ui-<PID>/report.json` 与截图覆盖 `0226、0228、0266、026C、028D、02A6、02CF、0090、00B4、00E7`。场景检查双层保存、配置保存失败回滚、不可读行禁止编辑，以及媒体图形点击、Naga 旧软件宏保持原执行类型和拒绝新绑定时零写入。Release 解决方案构建通过，零警告、零错误。

尚未使用实体设备验证侧板热插拔、按键实际输出、断电持久性和不同固件版本。重新开放 Naga 侧键软件绑定需要确认独立且可抑制的输入协议，并实现按设备和侧板定位的运行时桥接。
